# Build instructions (AMO source submission)

This package contains the unminified source of **Nesoi 标签管理器** (Nesoi Tab Manager).
The add-on package submitted to addons.mozilla.org contains code that is bundled by
[Vite](https://vitejs.dev/) (UI, Vue 3 SFC → minified chunks) and by
[esbuild](https://esbuild.github.io/) (background event page → single ESM file),
so these build instructions are provided as required by the
[Source code submission](https://extensionworkshop.com/documentation/publish/source-code-submission/) policy.

## Environment

The build was produced with the default AMO reviewer environment and needs nothing else:

- Ubuntu 24.04 (Desktop), x86_64 or ARM64
- Node.js 24.x (built with 24.14.0), npm 11.x (built with 11.9.0)
- No global tools. `git`, `zip` and `librsvg` are **not** required to reproduce the add-on package.

## Reproduce the add-on package

```bash
npm ci                # installs exactly the versions pinned in package-lock.json
npm run build:firefox # writes the Firefox add-on to dist/firefox/
```

`dist/firefox/` now contains exactly the files of the submitted `dist/nesoi-tab-manager-firefox-<version>.zip`:

```
dist/firefox/
├── manifest.json          # generated from manifest.json by scripts/write-manifest.mjs
├── background.js          # esbuild bundle of background.js + background/*.js
├── content_script.js
├── popup.html / popup.css / popup.js
├── icons/                 # PNG icons copied as-is from icons/
└── ui/                    # Vite build output of src/manager (manager.html, sidebar.html, assets/)
```

To rebuild both browser targets plus the release zips, run `npm run build` (additionally requires the
`zip` command line tool, which is only used to archive the finished directories).

The build is deterministic: Vite/esbuild chunk file names are content hashes, so rebuilding from this
source produces the same file names and the same file contents as the submitted package.

## What is generated and what is source

| Path | Origin |
| --- | --- |
| `manifest.json` | source (base manifest, used as-is for the Chrome target) |
| `dist/firefox/manifest.json` | generated by `scripts/write-manifest.mjs` |
| `ui/**` | build output of `src/manager/**` (Vite + Vue) — not included in this source package |
| `dist/**` | build output / release archives — not included in this source package |
| `icons/icon-*.png` | generated from `icons/icon.svg`; the PNGs are committed, and `npm run icons` (needs `rsvg-convert`) regenerates them but is **not** part of the AMO build |
| `scripts/**` | build, packaging and Node-only regression test scripts |

## Firefox-specific manifest keys

`dist/firefox/manifest.json` differs from the base `manifest.json` in the keys Firefox needs:

- `background.scripts` + `type: "module"` instead of `background.service_worker`
  (Firefox does not support MV3 service workers, see Firefox bug 1573659);
- `sidebar_action` for the native sidebar panel (`ui/sidebar.html`);
- `permissions` additionally contains `menus.overrideContext` (Firefox-only permission used to render
  the tab context menu items);
- `browser_specific_settings.gecko`: add-on id, `strict_min_version: "140.0"` and
  `data_collection_permissions`.

## Third-party code

All third-party code is installed from public npm packages listed in `package-lock.json`:

- [Vue 3](https://github.com/vuejs/core) (MIT) — bundled into `ui/assets/*.js` at build time.
- [Vite](https://github.com/vitejs/vite), [@vitejs/plugin-vue](https://github.com/vitejs/vite-plugin-vue)
  and [esbuild](https://github.com/evanw/esbuild) — build-time only, not shipped.

## Notes for reviewers

- `ui/assets/*.js` are minified by design (size only, no obfuscation); `src/manager/**` is the readable
  source for them.
- Static analyzer warnings about `UNSAFE_VAR_ASSIGNMENT` for `ui/assets/tree_core-*.js` point at Vue's
  own runtime-dom internals (it assigns `element.innerHTML = ""` / renders compiled templates), not at
  hand-written code of this add-on. All hand-written DOM text (including user-supplied list names) is set
  via `textContent`; see `appendSubItemContent()` in `popup.js`.
- No remote code is loaded at runtime. The only network request the add-on can perform is the optional
  AI grouping request (see below); it is disabled until the user configures an endpoint, an API key and a
  model in the add-on settings.
- **Data transmission:** by default the add-on transmits nothing. Only when the user explicitly clicks
  “AI 分组” does it POST the titles and base domains of the selected tabs (plus, optionally, the titles
  and descriptions of saved lists) to the endpoint the user configured themselves. That is declared as
  `data_collection_permissions.optional = ["browsingActivity", "websiteContent"]` and is gated by
  `chrome.permissions.request({ data_collection })` in `src/manager/utils/data_collection.js`.
- No analytics, telemetry, crash reporting or remote configuration of any kind.
