# 树状标签页（Tree Style Tab）

## 目标与范围
- 在管理页「打开的窗口」视图中提供树状展示，让用户看清标签页之间「谁打开了谁 / 谁被挂到谁下面」的层级关系。
- 参考 Firefox 扩展 Tree Style Tab（TST）的树模型与交互语义，但**不复制**其 Firefox 专有能力（垂直标签栏注入、`tabs.insertAfterCurrent` 等）。
  `sessions.setTabValue` 是唯一例外：只在 Firefox 下作为「原生撤销关闭」的精确识别手段使用（见「撤销关闭与树恢复」），Chrome 侧走自建关闭记录。
- 只有「打开的窗口」视图支持树状与平铺切换；保存的列表、冻结历史、近期标签页保持平铺。
- Firefox 下另提供原生侧边栏作为同一棵树的常驻入口（见 `docs/ui/firefox_sidebar.md`）；侧边栏以单条操作为主，另有多选模式的批量关闭/冻结/保存。
- 权限：在原有 `tabs` / `storage` / `alarms` 之外新增 `sessions`（最近关闭列表 + Firefox 侧 `setTabValue`），详见「权限」。

## 术语
- **父 / 子**：`child.parent = parent`，表示子标签挂在父标签之下。
- **顶层标签（root）**：没有父标签。
- **子树（subtree）**：某标签及其全部后代。
- **折叠（collapsed）**：折叠某标签的子树后，其后代在树视图中隐藏。这是**纯视图概念**，不改变树数据。
- **深度（depth）**：顶层为 0，子标签为父标签深度 + 1。

## 树数据的唯一真相
- 树是**本插件自己维护的数据**：后台按窗口在内存中维持，并持久化到 `chrome.storage.local`。
- `openerTabId` **只在三个时机**参与：
  1. 标签刚被创建、且后台当前持有该窗口的树时，用于确定它的**初始**父标签；
  2. 浏览器重启后的会话恢复中，持久化快照无法对齐的标签用它兜底；
  3. **撤销关闭恢复**的标签找不到原父（父标签也已被关闭）时的兜底。
- 父子关系一旦确定，**不再因为 `openerTabId` 后续变化而回写**（与 TST 的 `syncParentTabAndOpenerTab` 默认关闭一致）。改变父子关系的途径只有：标签创建、父标签被关闭后的提升、跨窗口迁移、撤销关闭恢复、用户在原生标签栏拖动（按新位置重新推断）、用户在管理页拖拽。
- **不变量**（任何时刻都必须成立）：
  - 父标签必须存在、在同一窗口、非固定（pinned）、且其 `index` 小于子标签的 `index`；
  - 固定标签一律为顶层，且不能作为任何标签的父；
  - 父子链无环（「父 index 严格小于子 index」这一条已足以排除环，因此不需要额外环检测）；
  - 同一父下的子标签在渲染与编码时按 `index` 升序排列——顺序是**读取时从标签的实际 index 派生**的，后台不存储兄弟顺序，
    因此每次结构变化都是 O(1) 更新，不需要为维护顺序做 O(n) 重排。
  - 违反上述条件的关系**先尝试就近改挂**：沿父链向上找到最近的「存活、排在子标签之前、非固定」的祖先，
    把关系改挂到它上面（与关闭标签时的 promote intelligently 同一口径）；整条链都没有存活祖先才降级为顶层，
    不向用户报错（只累积调试计数）。
    这一步**不能**用「直接落顶层」代替：父标签被关闭、被移走、或在树没进内存时被关闭，都会让关系暂时不合法，
    直接落顶层会把整棵子树凭空抬到根上——「关掉父标签后子标签全变顶层」正是这么来的。

## 父子关系的确定规则
### 1) 标签创建（`tabs.onCreated`）
- **被识别为「撤销关闭 / 重新打开」的标签优先套用关闭记录**（父标签与物理位置，见「撤销关闭与树恢复」），
  不走下面的 opener / 活动标签规则；记录中的父已不存在时落顶层，并保留浏览器给出的物理位置。
- 固定标签 → 顶层。
- 有 `openerTabId`，且 opener 同窗口、非固定、`opener.index < tab.index` → 挂到 opener 下，追加为**最后一个子标签**。
- 否则（无 opener 或 opener 不合法）：
  - 若后台持有「创建时刻的活动标签」（该窗口最近一次 `onActivated` / `onFocusChanged` 得到的活动标签），挂到它下面（等价于 TST 的 `autoAttachOnNewTabCommand = open as child`）；
  - 该活动标签也不合法 → 顶层。
- 若该窗口的树尚未加载：先加载一次（O(n) 对齐），再按上述规则挂载。

### 2) 关闭标签（`tabs.onRemoved`）——promote intelligently
设被关闭标签为 T，父为 P（可能为空），有序子标签列表为 C：
- **T 是顶层**：`C[0]` 变为顶层并接替 T 的位置，`C[1..]` 成为 `C[0]` 的子标签。
- **T 有父 P，且 T 是 P 的唯一子标签**：C 全部接到 P 下，保持相对顺序。
- **其余情况**：`C[0]` 接到 P 下并接替 T 的位置，`C[1..]` 成为 `C[0]` 的子标签。
- C 的「第一个 / 全部」按标签**实际物理 index** 判定，而不是按挂载先后：后台在提升前会先按物理下标注排序，
  否则经过若干次拖拽挂载后，「第一个子标签」会变得不确定。
- 与 TST 默认行为一致（配置项 `promoteAllChildrenWhenClosedParentIsLastChild` 默认开启）。
- **树还没进内存时的关闭**：MV3 的后台会被回收，`tabs.onRemoved` 到达时该窗口的树可能不在内存里。
  此时若有一次对齐正在进行（`loadingTrees` 命中），就把这次提升挂到那次加载上，树装好后立刻补做——
  加载用的标签列表是先 `queryWindowTabs` 再 `await storageGet` 得到的，关闭恰好落在这个空档时，
  树里会留下一个"幽灵父标签"（已关闭却仍作为别人的父）。补做提升后子标签照常接替，不会留幽灵。
  另外，随后任何一次落盘都会跑不变量校验作为兜底（见「不变量」），所以丢掉的提升也不会把快照写坏。
- 整窗关闭（`removeInfo.isWindowClosing`）→ 直接丢弃该窗口的树与快照，不做提升。

### 3) 原生标签栏拖动（`tabs.onMoved`）——按新位置重新推断
设移动后新位置的前一个 / 后一个非固定标签为 P / N（同窗口，排除被移动标签自身及其子树）。记 `level(x)` 为深度（顶层为 0），`parent(x)` 为父：
- 无 P（移到最前）→ 顶层。
- 无 N（移到最后）→ 若 P 的祖先链包含旧父，保持旧父；否则顶层。
- `parent(P) === parent(N)` → 成为 `parent(P)` 的子标签（与 P、N 同级）。
- `level(P) > level(N)` → 移到某棵已有树的末尾：
  - 位移 `|toIndex - fromIndex| < 2`（多半是键盘 / 程序移动）→ 父 = `parent(P)`；
  - 否则（多半是拖拽）→ 父 = 旧父（若存在），否则 `parent(N)`。
- `level(P) < level(N)` 且 `parent(N) === P` → 移到已有树的首个子位置 → 父 = P。
- 若推断出的父是被移动标签自身或其后代 → **无效移动，不修改树**（TST 用 `moveBack` 回滚物理位置，我们不做物理回滚）。
- 被移动标签的整棵子树保持原有父子关系。
- 规则移植自 TST 的 `detectTabActionFromNewPosition()`。

### 4) 跨窗口迁移（`tabs.onDetached` / `tabs.onAttached`）
- 标签离开窗口时，先记录下整棵子树的父子关系与物理顺序，再把它从原窗口树上摘除。
  Chrome 只会搬走被拖的那一个标签，所以子树必须由插件自己搬，父子关系也要自己保留。
- 到达新窗口时，**整棵子树一并迁移**（子标签用分批 `chrome.tabs.move` 移到新窗口，按原窗口的物理顺序排列），
  父子关系与相对顺序保持不变。
- 被移动标签在新窗口的父按规则 3 推断；推断不出则顶层。
- 分批移动避免一次性触发巨量事件。

### 5) 管理页拖拽
见「管理页交互 · 拖拽」。

## 持久化
### 存储位置
- `chrome.storage.local`
  - `treeStructure:<windowId>`：单个窗口的树快照。**按窗口分键**，使一次写入只需覆盖发生变化的窗口。
  - `treeStructureWindows`：窗口索引 `{ [windowId]: updatedAt }`，用于清理已消失窗口的键；体积很小，随快照一起写。
  - `treeViewMode`：管理页窗口视图的展示模式（`"tree"` / `"flat"`），全局一份。
- `chrome.storage.session`
  - `treeCollapsed`：折叠状态 `{ [windowId]: [tabId, ...] }`，仅当前浏览器会话有效（重启后全部展开）。会话存储是内存态，写入不落盘。
  - `treeSessionToken`：`{ token, at }`，本次浏览器会话的树结构令牌与**会话起点**。用来判断快照里的 `tabId` 是否还与当前标签同一批身份（见「会话恢复对齐算法」），以及每标签会话值是不是本次会话写的（见「层级自动修复」）。
  - `treeRepairDone`：`{ [windowId]: at }`，本会话已做过层级自动修复的窗口，避免每次树重建都重扫一遍。
  - `closedTabLog` / `closedGroups`：撤销关闭用的单标签记录栈与关闭组栈，同样只存活于当前会话（见「撤销关闭与树恢复」）。
- 不持久化 `openerTabId`（不可靠），不持久化除 URL / 标题之外的标签元数据。

### 快照结构
```jsonc
{
  "v": 2,                     // 结构版本，便于将来迁移
  "at": 1712345678901,        // 写入时间戳（毫秒）
  "n": 10000,                 // 标签数
  "sid": "s1m2n3...",         // 写入时的会话令牌（与 storage.session 的 treeSessionToken.token 比较）
  "items": [                  // 按浏览器 index 升序排列
    { "u": "https://example.com/", "t": "标题", "p": -1, "i": 1234 }
    // p = 父标签在 items 中的下标，-1 = 顶层；i = 写入时的 tabId（只在同一浏览器会话内可信）
  ]
}
```
- `u` 是**跨浏览器重启**唯一可用的配对依据（重启后 `tabId` 全部重新分配）；`i` 只在同一会话内有效，配合 `sid` 在 Service Worker / 事件页被回收后做精确配对。
- 体积估算：10K 标签约 1~2MB（`i` 约再占 100KB）。若序列化后超过 `SNAPSHOT_MAX_BYTES`（默认 4MB，定义在 `background/tree.js`），自动降级为**不写 `t`**；`u` / `p` / `i` 都不能丢。

### 会话恢复对齐算法（O(n log n)）
输入：窗口实际标签序列 `A`（按 index）、快照序列 `S`、当前会话令牌。
0. **同会话精确配对（v2 起）**：`S.sid` 与会话令牌一致时，`S[j].i` 就是权威身份，直接配对，不参与下面的 URL 猜测。
   因此 SW 被回收后重建时，**地址栏搜索/导航/重定向改了 URL、标签被 discard 拿不到 URL、多个标签 URL 完全相同，都不会影响身份**——父子关系不会因为"什么都没关、只是导航了一次"而丢失。
   令牌不一致（浏览器重启、或环境没有会话存储）时完全忽略 `i`，退回下面按 URL 的对齐；v1 旧快照没有 `i` / `sid`，同样走 URL 路径。
1. 为 `A` 建立 `url → 升序下标数组` 的索引。
2. **偏移估计**：从 `S` 开头若干项各自产生候选整体偏移（在 URL 索引里定位），再用「后续项能对上多少」打分选出最优。
   会话恢复最常见的情况是「顺序不变，但固定标签或初始标签页导致头部整体移位」，只要一步偏移估计即可完全对齐；
   打分是必需的：只看第一项会被这一项自身的位移带偏，得出荒谬偏移后整轮对齐都会失败。
3. **逐项就近配对**：以「期望下标 = j + 偏移」为中心，在 `±16` 的邻域内由近及远寻找同 URL 的未使用项，命中后就地修正偏移。
   邻域搜索是容忍局部乱序的关键——朴素的「单调游标贪心」会在一次错位后把后面所有项一起冲掉。
   偏移不为 0 的候选还必须通过「下一项也能就近接上」的确认，否则浏览器里大量重复的空白页会把配对引到错误位置。
   三个例外：
   - 该 URL 在实际序列里**只出现一次**时跳过确认——候选必然就是它本人，不存在配错位置的可能；
     否则紧跟其后的标签刚被关闭就会让确认失败，这个唯一项被误判为「新增标签」，连同它的父子关系一起丢失。
   - 某个快照项本轮**配不上**（通常是标签已被关闭）时，把偏移 `-1`：它后面的项在实际序列里整体左移了一位。
     不做这一步，「位置优先」会让随后同名 URL 的连续项（连续多个新标签页 / `about:blank`）整体错位一个槽位，
     末尾项被挤成「新增标签」，父子关系随之断裂。
   - 实际标签的 URL **不可用或不可信**时（已卸载 / 冻结的标签正是如此：Firefox 曾经完全取不到 URL，
     现在也可能给出 `about:blank`），不能拿 URL 去否定候选。这类标签视为「身份不可知」，退化为**按位置配对**；
     否则整项会被判成「新增标签」，连同它在快照里的父子关系一起丢失——表现为整棵子树被抬到顶层。
     该兜底只接受「身份不可知」的候选，身份明确的标签仍严格按 URL 匹配。
4. **有界前向搜索**：邻域内找不到时，用 URL 索引向前查找，但限制跳距（256）并要求下一项确认，兜住「中间被插入一大段新标签」。
5. **父关系恢复**：对每个配对项，若 `S[j].p >= 0` 且对应项也已配对且位置在子之前，则 `parent = 实际下标(S[j].p)`；
   若对应项**没有配上**（父标签已被关闭）或位置异常，则沿快照的父链继续向上，取最近的「已配对且位置在子之前」的祖先作为父。
   这正是「关闭标签」一节里 promote intelligently 的对齐版本：子标签提升到祖父，而不是被凭空抬成顶层。
   整条父链都没有存活祖先（含 `S[j].p = -1`）才落顶层——父标签必须真实存在是硬性不变量。
6. 未配对的新增标签：用 `openerTabId` 兜底，无则顶层。
7. 最后统一跑不变量校验（父在子前、无环、pinned 规则）：违反者先按第 5 步同一口径就近改挂到最近的存活祖先，
   整条链都没有存活祖先才降级为顶层。
- `S[j].u` 为空时按位置就近配对（`about:blank` 等无法用 URL 区分）。
- 复杂度 O(n log n)；10K 下实测 < 20ms。
- **URL 变了必须回写**：同会话配对时若发现实际标签的 URL 与快照不一致（导航过），本次对齐不算 `exact`，
  会触发一次回写——URL 是跨重启唯一的配对依据，留在磁盘上的旧 URL 会让下一次重启配不上。
- 该算法**不使用** TST 的 `findStructureOffset`（其 `indexOf` 写法在有重复 URL 时可能是 O(n²)）。
- 10K 标签、5% 完全乱序的压力场景下配对率约 95%（未配对数量 ≈ 被交换标签数的两倍），其余退化为顶层或按 opener 兜底。

### 写入节流
- 后台只在内存中改树并置 `dirty`，**不立即写盘**。
- 落盘时机（任一满足）：
  1. 结构稳定空闲 `FLUSH_IDLE_MS`（默认 5000ms）后；
  2. 结构变化过快（累计变化次数 > `FLUSH_BURST_CHANGES`，默认 200）时，空闲等待延长为 `FLUSH_BURST_IDLE_MS`（默认 15000ms），避免批量操作期间反复写盘；
  3. 定时兜底 alarm `treeFlush`：仅在有脏数据时创建，周期 5 分钟；
  4. `chrome.runtime.onSuspend`（SW 即将被回收）时尽力写一次。
- 每次写入只覆盖**发生变化的窗口**（按窗口分键），并同步更新索引键。写入前会统一跑一次不变量校验，
  保证磁盘上的数据永远合法；该校验会把"父标签已经不在窗口里"的子标签接回最近的存活祖先，
  而不是把它们抬成顶层，因此即使某次关闭事件被丢掉，快照也不会被写成"子树脱离原层级"的样子。
  这也是内存树与磁盘快照之间最后一道纠偏：内存树里的幽灵父标签在这里被消化掉。
- 预期：日常浏览下每分钟个位数次写入、每次仅一个窗口的快照；浏览器启动恢复期间为 0 次。

### 启动性能
- 后台顶层**不做任何树计算**，只注册事件监听（成本与现有 `discard` / `recentTabs` 模块同级）。
- 浏览器启动 / 会话恢复期间进入「启动静默期」：
  - 起点：`chrome.runtime.onStartup` / `onInstalled`；此外在 SW 冷启动后的 5 秒内若观察到 ≥20 次结构事件，
    也判定为「正在恢复会话」——这是兜底，防止 `onStartup` 晚于会话恢复的首批 `tabs` 事件。
    该兜底只在冷启动窗口内生效，正常使用中批量关闭标签不会误触发。
  - 结束：连续 `STARTUP_QUIET_MS`（默认 10000ms）无结构事件，或达到 `STARTUP_MAX_GRACE_MS`（默认 60000ms）上限；
  - 期间所有结构事件只置「该窗口需要重建」标记，**不加载快照、不做对齐、不写盘**。
- 静默期结束后，或用户打开管理页请求树数据时，才对被标记的窗口做一次对齐重建。
- 因此 10K 标签的启动恢复不会产生逐事件的 O(n) 重复对齐，也不会产生磁盘写入。

## 撤销关闭与树恢复（新增）

### 目标与边界
- **整组恢复**：本插件自己发起的批量关闭（①「关闭整棵子树」②管理页 / 侧边栏多选后的批量关闭 ③保存后关闭）
  记为一个**关闭组**；撤销时把组内标签连同父子关系、兄弟顺序与物理位置一起恢复。
- **单标签恢复**：浏览器原生的「重新打开已关闭的标签页」（Ctrl+Shift+T 或原生右键菜单）恢复单个标签时，
  把它挂回原父节点与原物理位置。
- **不做**：浏览器没有「一组关闭」的概念，因此原生 Ctrl+Shift+T 永远只恢复被点开的那一个标签，不会连带恢复整组；
  想整组回来必须用本插件自己的撤销入口。关闭记录只存活于当前浏览器会话，重启后不做恢复。
- 撤销是**用户显式操作**触发的；插件不会在无人操作时移动标签页。这是「位置稳定性」一节的唯一例外。

### 关闭记录（`chrome.storage.session`）
- `closedTabLog`：**单标签**关闭记录栈，容量 `CLOSED_LOG_MAX`（拟 50）。
  每条：`{ tabId, windowId, parentId, prevId, nextId, index, pinned, url, title, at }`。
- `closedGroups`：**关闭组**栈，容量 `CLOSED_GROUP_MAX`（拟 5）。
  每组：`{ groupId, windowId, at, label, structure, members: [...] }`，成员为
  `{ tabId, url, title, index, parentIndex, parentId, prevId, nextId, pinned, collapsed }`：
  `parentIndex` 是父成员在组内的下标（`-1` 表示父不在这组里），`parentId` 用于"父还开着、但它不在这组里"的情况
  （关掉几个子标签后仍要挂回原父），`prevId` / `nextId` 是关闭那一刻的原物理邻居，用于把标签放回原位附近。
  `structure` 为 false 表示这一组降级为"只记成员、不记结构"。
- **为什么可以直接存 `tabId`**：同一浏览器会话内 `tabId` 不复用，而记录只在这个会话内有效，
  因此不需要 TST 那种 `uniqueId` 稳定身份映射——这是「不跨重启」这条边界换来的简化。
- 单组超过 `GROUP_MAX_MEMBERS`（拟 500）时**降级**：只记成员 URL、不记结构，避免一次关闭大树把 `storage.session`
  配额撑爆；这种组恢复后是平铺的，不会恢复出错误层级。
- 写入时机：**关闭动作发生前**一次性写入（此刻树还完整），关闭结束后按实际结果剔除「其实没被关掉」的成员
  （例如 `beforeunload` 取消了关闭）。

### 关闭侧的成组口径
- 只有**本插件发起的批量关闭**成组：新增后台函数 `closeTabsAsGroup()`，管理页与侧边栏的批量关闭入口统一走它。
- 「关闭整棵子树」= 关闭被操作标签**及其全部后代**（用 `collectSubtreeIds()` 取集合），
  入口见 `docs/ui/manager_ui.md` 与 `docs/ui/firefox_sidebar.md`。
- 单标签关闭（行内 ×、中键、Ctrl+W 等）只进 `closedTabLog`，不成组。

### 恢复流程（整组）
1. 取 `closedGroups` 栈顶一组（本次只支持撤销最近一组）；原窗口已关闭时落到当前窗口。
2. 优先用 `chrome.sessions.getRecentlyClosed()` + `chrome.sessions.restore()` 恢复浏览器仍记得的会话
   （保住前进后退历史），最多 `chrome.sessions.MAX_SESSION_RESULTS` 个——Chrome 下只有约 25 个，
   因此稍大的组必然落到第 3 步。
3. 其余成员按记录中的 `url` / `title` 重新打开（后台打开、不激活、不冻结）。
4. 组内成员若已被原生撤销提前恢复（`tabId` 不同），复用该实例，不重复打开。
5. 按记录结构重建父子（`setParent`），再用分批 `chrome.tabs.move` 把成员移回原物理顺序与位置。
6. 收尾跑一次 `sanitizeTreeState()` 不变量校验，并**激活组内第一个标签**（按原顺序）。
7. 恢复完成后该组出栈；任何一步失败都只影响这一组，不破坏现有树。

### 恢复流程（单标签 / 原生撤销）
- **Firefox**：树结构变化时把 `{ parentId, at }` 写进 `sessions.setTabValue(tabId, "nesoi:tree-ref", …)`，
  标签被原生恢复时用 `sessions.getTabValue()` 读回 → **精确识别**，再按关闭记录里的父/邻居挂回原父与原位置。
  会话值只用来回答"这是不是一次撤销关闭"（以及取更新的父标签）；完整的现场（父 + 前后邻居 + 下标）
  仍以关闭记录为准——它在关闭那一刻同步抓取，比防抖写入的会话值更准。
  （实现时需先确认 Firefox 的 `chrome.*` 命名空间下这两个方法的调用形式——本插件统一走 `chrome.*` 别名，
  `sessions.setTabValue` 属 Firefox 专有 API。）
- **Chrome**：没有等价的每标签会话值，只能启发式识别——用 `closedTabLog` **栈顶**记录与新建标签的 URL 全等匹配，
  命中即认领出栈；记录带 TTL（拟 5 分钟），插件自己发起的打开直接跳过匹配。
- 识别失败、或记录中的父已不存在 → 退回原有规则（opener / 位置推断），**不报错、不破坏现有树**。
- 这条路径是**尽力而为**：URL 被重定向改写、或刚关掉又手动打开同一 URL 时可能误判 / 漏判，这是 Chrome 侧 API 的固有上限。
- **会话值必须在树已加载时写入**：写入入口是结构变化后的 250ms 防抖任务，旧实现在这一刻若树还不在内存里
  （后台刚被回收、或与 500ms 的树加载防抖撞在一起）会静默跳过，于是那个标签永远没有会话值，
  之后原生撤销它只能落顶层。现在该任务会先 `ensureTreeFor()` 把树准备好再写。

### 层级自动修复（用每标签会话值救援历史损坏）
- **背景**：旧版本在若干时序下会把整棵子树写成顶层（快照里 `p = -1`），原父信息已经丢失，靠快照无法还原。
- **唯一可用来源**：Firefox 的每标签会话值（`nesoi:tree-ref`）按 `tabId` 保存父引用，能跨 SW 回收存活、也随标签恢复，
  因此可以在树刚从快照重建完成时，把它当作救援依据。
- **触发点**：`loadTree()` 装好树之后调用钩子（由 `closed_groups.js` 注册），异步后台执行，不阻塞首次读取。
- **安全边界**（任一不满足即跳过）：
  - 只在 Firefox（有每标签会话值）且能写 `storage.session` 时执行；
  - 只处理**当前是顶层**的非固定标签（已经有父的说明结构完好，一律不动）；
  - 会话值必须写于**本会话内**（`at >= treeSessionToken.at`）——上一次浏览器会话的值里 `tabId` 可能已被复用；
  - 最终仍走 `applyRestoredParent` 的不变量校验（父存活、同窗口、非固定、排在子之前、不成环），
    校验不过仍是落顶层，不会产生非法结构。
- **频次与开销**：按窗口记在 `treeRepairDone`，每个浏览器会话最多扫一次；批量并发读取（`REPAIR_BATCH_SIZE`），
  单窗口上限 `REPAIR_MAX_TABS`（4000）。修复成功后会把修正过的结构落盘。
- **边界**：这是尽力而为的一次性救援——会话值本身缺失或已被覆盖时无法还原，用户手动拖回一次即可。

### 与既有机制的关系
- 恢复出的标签同样受「不变量」约束（父在子前、pinned 不参与父子、无环），违反者降级为顶层。
- 恢复期间会产生一批 `tabs.onCreated`：按窗口合并处理，避免逐条做 O(n) 对齐。
- 关闭记录与 `treeStructure:<windowId>` 快照是两件事：前者服务「撤销关闭」，后者服务「浏览器重启后对齐」，互不替代。

## 消息协议（新增）
- `getTreeStructure`
  - 参数：`{ windowIds?: number[] }`（缺省返回所有窗口）
  - 返回：`{ ok, structures: { [windowId]: { parents: { [tabId]: parentTabId } } } }`
    —— `parents` **只包含有父标签的条目**，缺省即顶层（10K 标签下可省掉约一半载荷）。
  - 用途：管理页渲染树状视图。只传父子映射，深度、折叠、渲染顺序都在 UI 侧计算，避免额外的 IPC 体积。
- `moveTabTree`
  - 参数：`{ tabId, parentId, afterTabId?, beforeTabId? }`（`parentId` 为 `null` 表示顶层）
  - 返回：`{ ok, moved, skipped, parentId }` 或 `{ ok: false, error }`（中文提示）
  - 语义：先改父子关系，再用一次（可分批）`chrome.tabs.move` 把「被拖标签 + 其整棵子树」按 DFS 顺序落到目标位置。
  - 校验：拒绝跨窗口、拒绝固定标签参与父子、拒绝挂到自身或自身子孙之下。
- `closeTabsAsGroup`
  - 参数：`{ windowId, tabIds, label }`
  - 返回：`{ ok, groupId, removed, skipped }` 或 `{ ok: false, error }`
  - 语义：先写 `closedGroups` 记录，再分批关闭（单批上限与批间隔沿用现有批量关闭策略）。
    只有走这条消息的关闭才成组；其余关闭入口只写 `closedTabLog`。
- `restoreClosedGroup`
  - 参数：`{ windowId? }`（缺省 = 最近一组）
  - 返回：`{ ok, groupId, restored, skipped, windowId }` 或 `{ ok: false, error }`（中文提示）
  - 语义：执行「恢复流程（整组）」；没有可恢复的组时返回明确的中文错误，由 UI 直接展示。
- 折叠状态由管理页直接读写 `chrome.storage.session`，不经后台。

## 管理页交互
### 视图切换
- 「打开的窗口」视图标题栏新增「树状 / 平铺」切换按钮。
- 默认 **树状**；选择写入 `chrome.storage.local` 的 `treeViewMode`（全局一份，切换时写一次，写入量可忽略）。

### 树状渲染
- 渲染顺序为**树的 DFS 顺序**：父 → 其整棵子树 → 下一个兄弟；兄弟之间按 `index` 升序。
- 行高保持 44px 不变（复用现有 `VirtualList`）；层级用左侧缩进（每层 16px，超过 12 层不再增加）与层级连线表示。
- 有子标签的行显示折叠三角（▸ / ▾）；点击即折叠 / 展开，只影响视图。
- 折叠状态存 `chrome.storage.session` 的 `treeCollapsed`；切换时立即更新视图，写入防抖 500ms。
- 深度由 UI 侧一次 O(n) 计算，不额外占用 IPC。

### 与筛选、选择的关系
- **过滤模式**：保留「匹配项 + 其全部祖先」；祖先行以非匹配样式展示，且不计入「匹配数」；某窗口整组无匹配则隐藏该窗口。
- **匹配行高亮**：只在"列表里混有非匹配行"时才启用。树状 + 过滤必然如此（祖先行不是匹配项），因此这两种模式的组合也必须高亮，否则用户无法把匹配项与路径行区分开；
  平铺 + 过滤时每一行都是匹配项，不做整表高亮。
- **跳转模式**：保持完整树，匹配行高亮，↑ / ↓ 在当前树的可见行之间循环跳转。
- **"标记匹配"与"只保留匹配"是两个独立开关**：`matchId` 决定哪些行算匹配项（两种模式都要传，跳转模式靠它高亮与导航），
  `pruneToMatches` 决定是否把非匹配行裁掉（只有过滤模式为真）。两者混用会让跳转模式退化成过滤，
  或者反过来让界面一直显示"无匹配"。
- **折叠与筛选**：只要存在关键词（两种模式都算），渲染时就**忽略折叠状态**（自动全展开），
  保证匹配项一定可见、↑/↓ 能跳到每一个匹配项；清除关键词后恢复用户的折叠状态。
- **被隐藏标签的子标签就近提升**：开启「隐藏已冻结」后，若某标签的父标签不可见，则把它提升到最近的可见祖先之下，
  避免出现「父行不显示、子行却缩进」的悬空行。
- **全选 / 清空**：过滤模式只作用于真正匹配的标签（祖先只是路径，不参与批量操作）；跳转模式作用于完整列表。
- 选中集合仍按 `tabId` 记录，与平铺模式完全一致。

### 拖拽
- 树状模式下拖拽**仅限同一窗口**；跨窗口请使用现有「移动到」功能。
- 被拖拽标签的**整棵子树**一起移动。
- 落点分区（与 TST 一致）：
  - 行的上 1/4 → 插到该行**之前**，成为其**兄弟**（父 = 目标行的父）；
  - 行的下 1/4 → 插到该行**之后**（含该行整棵子树之后），成为其**兄弟**；
  - 行的中间 1/2 → 成为该行的**子标签**，追加为其**最后一个子标签**。
- 拖拽过程中显示落点指示（兄弟 → 插入线；子标签 → 目标行高亮）。
- **无效落点**（目标是自身或自身后代、目标或被拖项是固定标签、跨窗口）→ 不显示指示、不触发操作。
- 拖拽结束后：先更新后台内存树，再用一次（可分批）`chrome.tabs.move` 把「被拖标签 + 其子树」按 DFS 顺序移动到目标物理位置，使物理顺序向树顺序靠拢。
- 这是**除跨窗口子树迁移与撤销关闭恢复外，插件唯一会移动标签页的场景**；其余情况下非用户操作时插件绝不移动标签页。

### 位置稳定性
- 树视图按 DFS 顺序渲染，可能与浏览器标签栏的物理顺序不一致（例如某子标签物理上离父标签很远，仍会显示在父标签正下方）。这是**有意设计**：插件不为了「子树物理连续」而在用户未操作时改动标签栏。
- 原生标签栏拖动会按位置重新推断父子（规则 3），因此用户在标签栏里的拖动依然能改变树。

### 关闭整棵子树 / 撤销关闭
- 树状模式下每行提供「关闭整棵子树」（关闭该标签及其全部后代），走后台 `closeTabsAsGroup` 成组。
- 视图标题栏提供「撤销关闭」按钮：撤销最近一组，无记录时禁用。
- 折叠、筛选、选择等既有交互不受影响；恢复完成后按现有事件机制刷新。
- 详细交互与文案见 `docs/ui/manager_ui.md`。

## 性能验收
- `scripts/bench_tree.mjs`（`npm run bench:tree`）对 `background/tree_core.js` 的纯函数做 10K 级基准：
  - 从 10K 标签构建树（含不变量校验）；
  - 从 10K 标签生成快照并序列化（输出字节数）；
  - 会话恢复对齐：完全一致 / 头部插入 200 / 中间插入 100 / 关闭 50 / 局部乱序 100 组 / 5% 完全乱序；
  - DFS 扁平化（折叠与全展开）、单次关闭提升、单次位置推断。
- 阈值（超出即失败）：建树 < 50ms、快照编码 < 50ms、对齐 < 100ms、扁平化 < 30ms；实际耗时约为阈值的 1/5~1/3。
- 单窗口 10K 标签的快照体积：约 1.2MB（含标题）/ 0.5MB（不含标题），低于默认 10MB 的 `storage.local` 配额。
- 复杂度要求：以上全部为 O(n) 或 O(n log n)，禁止 O(n²)。基准脚本会同时校验不变量（父在子前、固定标签不参与父子），
  防止为了性能牺牲正确性。
- `scripts/test_tree.mjs`（`npm run test:tree`）用一套 chrome API 模拟覆盖后台事件链路：
  建树、创建挂载、关闭提升（唯一子标签 / 多子标签）、原生拖动重推断、管理页拖拽、非法拖拽拒绝、
  跨窗口子树迁移、落盘与重启恢复。
- `scripts/test_tree_ui.mjs` 覆盖管理页行构建：DFS 顺序与深度、折叠隐藏子树、筛选补祖先并忽略折叠、
  隐藏已冻结时的就近提升、平铺模式回归、全选口径。
- `scripts/test_closed_groups.mjs`（并入 `npm run test:tree`）覆盖撤销恢复链路：
  关闭整棵子树 → 撤销 → 层级 / 顺序 / 物理位置一致；多选跨父关闭 → 各自回到原父；
  组容量淘汰与 TTL 过期；记录中的父已关闭 → 降级顶层；`storage.session` 记录在 SW 被回收后仍可用；
  恢复后不变量（父在子前、pinned 不参与父子、无环）全部成立。
  复杂度要求 O(k log k)（k = 组内标签数），禁止 O(n²)。

## 权限
- 在原有的 `tabs`、`storage`、`alarms` 之外新增 **`sessions`**，Chrome 与 Firefox 目标清单都写：
  - 读最近关闭列表（`sessions.getRecentlyClosed`）并恢复（`sessions.restore`）——整组撤销需要；
  - Firefox 侧的 `sessions.setTabValue` / `sessions.getTabValue`——原生撤销的精确识别需要。
- 该权限在 Chrome 侧属低风险权限；在 Firefox（AMO）侧属于**新增必需权限**，已安装用户更新时会遇到一次重新授权
  （`about:debugging` 临时加载无感），代价口径见 `docs/ui/firefox_sidebar.md` 的「权限」一节。
- 不读取 `chrome.tabGroups`，不新增内容脚本逻辑，不在网页上下文做任何事。

## 已知限制
- Chrome 无 Firefox `sessions.setTabValue` 级别的稳定标签标识，因此跨浏览器重启的树恢复是**尽力而为**：URL 变化、顺序大幅变化、或大量重复 URL 时可能退化为顶层。
- **原生 Ctrl+Shift+T 的整组恢复不做**：浏览器没有「一组关闭」的概念，只有被点开的那一个标签会被恢复；整组回来请用本插件的「撤销关闭」入口。
- Chrome 侧的原生撤销识别是**启发式**（栈顶记录 + URL 全等 + TTL）：重定向改写了 URL、或刚关掉又手动打开同一 URL 时可能误判 / 漏判；Firefox 侧走 `setTabValue`，识别是精确的。
- 关闭记录只存活于当前浏览器会话（`chrome.storage.session`），浏览器重启后不可撤销。
- 单组超过 `GROUP_MAX_MEMBERS` 的关闭组只恢复成员、不恢复层级。
- Chrome 下 `openerTabId` 在部分场景并不可靠（例如 Ctrl+T），需要靠位置规则与快照对齐纠正。
- 不参与 `chrome.tabGroups` 原生分组。
- 折叠状态不跨浏览器重启保留。
