# 树状标签页（Tree Style Tab）

## 目标与范围
- 在管理页「打开的窗口」视图中提供树状展示，让用户看清标签页之间「谁打开了谁 / 谁被挂到谁下面」的层级关系。
- 参考 Firefox 扩展 Tree Style Tab（TST）的树模型与交互语义，但**不复制**其 Firefox 专有能力（垂直标签栏注入、`sessions.setTabValue`、`tabs.insertAfterCurrent` 等）。
- 只有「打开的窗口」视图支持树状与平铺切换；保存的列表、冻结历史、近期标签页保持平铺。
- **不新增任何浏览器权限**（详见「权限」）。

## 术语
- **父 / 子**：`child.parent = parent`，表示子标签挂在父标签之下。
- **顶层标签（root）**：没有父标签。
- **子树（subtree）**：某标签及其全部后代。
- **折叠（collapsed）**：折叠某标签的子树后，其后代在树视图中隐藏。这是**纯视图概念**，不改变树数据。
- **深度（depth）**：顶层为 0，子标签为父标签深度 + 1。

## 树数据的唯一真相
- 树是**本插件自己维护的数据**：后台按窗口在内存中维持，并持久化到 `chrome.storage.local`。
- `openerTabId` **只在两个时机**参与：
  1. 标签刚被创建、且后台当前持有该窗口的树时，用于确定它的**初始**父标签；
  2. 浏览器重启后的会话恢复中，持久化快照无法对齐的标签用它兜底。
- 父子关系一旦确定，**不再因为 `openerTabId` 后续变化而回写**（与 TST 的 `syncParentTabAndOpenerTab` 默认关闭一致）。改变父子关系的途径只有：标签创建、父标签被关闭后的提升、跨窗口迁移、用户在原生标签栏拖动（按新位置重新推断）、用户在管理页拖拽。
- **不变量**（任何时刻都必须成立）：
  - 父标签必须存在、在同一窗口、非固定（pinned）、且其 `index` 小于子标签的 `index`；
  - 固定标签一律为顶层，且不能作为任何标签的父；
  - 父子链无环（「父 index 严格小于子 index」这一条已足以排除环，因此不需要额外环检测）；
  - 同一父下的子标签在渲染与编码时按 `index` 升序排列——顺序是**读取时从标签的实际 index 派生**的，后台不存储兄弟顺序，
    因此每次结构变化都是 O(1) 更新，不需要为维护顺序做 O(n) 重排。
  - 任何违反上述条件的关系都降级为「顶层」，不向用户报错（只累积调试计数）。

## 父子关系的确定规则
### 1) 标签创建（`tabs.onCreated`）
- 固定标签 → 顶层。
- 有 `openerTabId`，且 opener 同窗口、非固定、`opener.index < tab.index` → 挂到 opener 下，追加为**最后一个子标签**。
- 否则（无 opener 或 opener 不合法）：
  - 若后台持有「创建时刻的活动标签」（该窗口最近一次 `onActivated` / `onFocusChanged` 得到的活动标签），挂到它下面（等价于 TST 的 `autoAttachOnNewTabCommand = open as child`）；
  - 该活动标签也不合法 → 顶层。
- 若该窗口的树尚未加载：先加载一次（O(n) 对齐），再按上述规则挂载。

### 2) 关闭标签（`tabs.onRemoved`）——promote intelligently
设被关闭标签为 T，父为 P（可能为空），有序子标签列表为 C：
- **T 是顶层**：`C[0]` 变为顶层并接替 T 的位置，`C[1..]` 成为 `C[0]` 的子标签。
- **T 有父 P，且 T 是 P 的唯一子标签**：C 全部接到 P 下，保持相对顺序。
- **其余情况**：`C[0]` 接到 P 下并接替 T 的位置，`C[1..]` 成为 `C[0]` 的子标签。
- C 的「第一个 / 全部」按标签**实际物理 index** 判定，而不是按挂载先后：后台在提升前会先按物理下标注排序，
  否则经过若干次拖拽挂载后，「第一个子标签」会变得不确定。
- 与 TST 默认行为一致（配置项 `promoteAllChildrenWhenClosedParentIsLastChild` 默认开启）。
- 整窗关闭（`removeInfo.isWindowClosing`）→ 直接丢弃该窗口的树与快照，不做提升。

### 3) 原生标签栏拖动（`tabs.onMoved`）——按新位置重新推断
设移动后新位置的前一个 / 后一个非固定标签为 P / N（同窗口，排除被移动标签自身及其子树）。记 `level(x)` 为深度（顶层为 0），`parent(x)` 为父：
- 无 P（移到最前）→ 顶层。
- 无 N（移到最后）→ 若 P 的祖先链包含旧父，保持旧父；否则顶层。
- `parent(P) === parent(N)` → 成为 `parent(P)` 的子标签（与 P、N 同级）。
- `level(P) > level(N)` → 移到某棵已有树的末尾：
  - 位移 `|toIndex - fromIndex| < 2`（多半是键盘 / 程序移动）→ 父 = `parent(P)`；
  - 否则（多半是拖拽）→ 父 = 旧父（若存在），否则 `parent(N)`。
- `level(P) < level(N)` 且 `parent(N) === P` → 移到已有树的首个子位置 → 父 = P。
- 若推断出的父是被移动标签自身或其后代 → **无效移动，不修改树**（TST 用 `moveBack` 回滚物理位置，我们不做物理回滚）。
- 被移动标签的整棵子树保持原有父子关系。
- 规则移植自 TST 的 `detectTabActionFromNewPosition()`。

### 4) 跨窗口迁移（`tabs.onDetached` / `tabs.onAttached`）
- 标签离开窗口时，先记录下整棵子树的父子关系与物理顺序，再把它从原窗口树上摘除。
  Chrome 只会搬走被拖的那一个标签，所以子树必须由插件自己搬，父子关系也要自己保留。
- 到达新窗口时，**整棵子树一并迁移**（子标签用分批 `chrome.tabs.move` 移到新窗口，按原窗口的物理顺序排列），
  父子关系与相对顺序保持不变。
- 被移动标签在新窗口的父按规则 3 推断；推断不出则顶层。
- 分批移动避免一次性触发巨量事件。

### 5) 管理页拖拽
见「管理页交互 · 拖拽」。

## 持久化
### 存储位置
- `chrome.storage.local`
  - `treeStructure:<windowId>`：单个窗口的树快照。**按窗口分键**，使一次写入只需覆盖发生变化的窗口。
  - `treeStructureWindows`：窗口索引 `{ [windowId]: updatedAt }`，用于清理已消失窗口的键；体积很小，随快照一起写。
  - `treeViewMode`：管理页窗口视图的展示模式（`"tree"` / `"flat"`），全局一份。
- `chrome.storage.session`
  - `treeCollapsed`：折叠状态 `{ [windowId]: [tabId, ...] }`，仅当前浏览器会话有效（重启后全部展开）。会话存储是内存态，写入不落盘。
- 不持久化 `openerTabId`（不可靠），不持久化除 URL / 标题之外的标签元数据。

### 快照结构
```jsonc
{
  "v": 1,                     // 结构版本，便于将来迁移
  "at": 1712345678901,        // 写入时间戳（毫秒）
  "n": 10000,                 // 标签数
  "items": [                  // 按浏览器 index 升序排列
    { "u": "https://example.com/", "t": "标题", "p": -1 }  // p = 父标签在 items 中的下标，-1 = 顶层
  ]
}
```
- 存 `url` / `title` 而不是 `tabId`：Chrome 重启后 `tabId` 会改变，只能用「顺序 + URL/标题」重新对齐。
- 体积估算：10K 标签约 1~2MB。若序列化后超过 `SNAPSHOT_MAX_BYTES`（默认 4MB，定义在 `background/tree.js`），自动降级为**不写 `t`**，只用 URL 对齐。

### 会话恢复对齐算法（O(n log n)）
输入：窗口实际标签序列 `A`（按 index）、快照序列 `S`。
1. 为 `A` 建立 `url → 升序下标数组` 的索引。
2. **偏移估计**：从 `S` 开头若干项各自产生候选整体偏移（在 URL 索引里定位），再用「后续项能对上多少」打分选出最优。
   会话恢复最常见的情况是「顺序不变，但固定标签或初始标签页导致头部整体移位」，只要一步偏移估计即可完全对齐；
   打分是必需的：只看第一项会被这一项自身的位移带偏，得出荒谬偏移后整轮对齐都会失败。
3. **逐项就近配对**：以「期望下标 = j + 偏移」为中心，在 `±16` 的邻域内由近及远寻找同 URL 的未使用项，命中后就地修正偏移。
   邻域搜索是容忍局部乱序的关键——朴素的「单调游标贪心」会在一次错位后把后面所有项一起冲掉。
   偏移不为 0 的候选还必须通过「下一项也能就近接上」的确认，否则浏览器里大量重复的空白页会把配对引到错误位置。
4. **有界前向搜索**：邻域内找不到时，用 URL 索引向前查找，但限制跳距（256）并要求下一项确认，兜住「中间被插入一大段新标签」。
5. 对每个配对项：若 `S[j].p >= 0` 且对应项也已配对且位置在前，则 `parent = 实际下标(S[j].p)`；否则用 `openerTabId` 兜底。
6. 未配对的新增标签：用 `openerTabId` 兜底，无则顶层。
7. 最后统一跑不变量校验（父在子前、无环、pinned 规则），违反者降级为顶层。
- `S[j].u` 为空时按位置就近配对（`about:blank` 等无法用 URL 区分）。
- 复杂度 O(n log n)；10K 下实测 < 20ms。
- 该算法**不使用** TST 的 `findStructureOffset`（其 `indexOf` 写法在有重复 URL 时可能是 O(n²)）。
- 10K 标签、5% 完全乱序的压力场景下配对率约 95%（未配对数量 ≈ 被交换标签数的两倍），其余退化为顶层或按 opener 兜底。

### 写入节流
- 后台只在内存中改树并置 `dirty`，**不立即写盘**。
- 落盘时机（任一满足）：
  1. 结构稳定空闲 `FLUSH_IDLE_MS`（默认 5000ms）后；
  2. 结构变化过快（累计变化次数 > `FLUSH_BURST_CHANGES`，默认 200）时，空闲等待延长为 `FLUSH_BURST_IDLE_MS`（默认 15000ms），避免批量操作期间反复写盘；
  3. 定时兜底 alarm `treeFlush`：仅在有脏数据时创建，周期 5 分钟；
  4. `chrome.runtime.onSuspend`（SW 即将被回收）时尽力写一次。
- 每次写入只覆盖**发生变化的窗口**（按窗口分键），并同步更新索引键。写入前会统一跑一次不变量校验，
  保证磁盘上的数据永远合法。
- 预期：日常浏览下每分钟个位数次写入、每次仅一个窗口的快照；浏览器启动恢复期间为 0 次。

### 启动性能
- 后台顶层**不做任何树计算**，只注册事件监听（成本与现有 `discard` / `recentTabs` 模块同级）。
- 浏览器启动 / 会话恢复期间进入「启动静默期」：
  - 起点：`chrome.runtime.onStartup` / `onInstalled`；此外在 SW 冷启动后的 5 秒内若观察到 ≥20 次结构事件，
    也判定为「正在恢复会话」——这是兜底，防止 `onStartup` 晚于会话恢复的首批 `tabs` 事件。
    该兜底只在冷启动窗口内生效，正常使用中批量关闭标签不会误触发。
  - 结束：连续 `STARTUP_QUIET_MS`（默认 10000ms）无结构事件，或达到 `STARTUP_MAX_GRACE_MS`（默认 60000ms）上限；
  - 期间所有结构事件只置「该窗口需要重建」标记，**不加载快照、不做对齐、不写盘**。
- 静默期结束后，或用户打开管理页请求树数据时，才对被标记的窗口做一次对齐重建。
- 因此 10K 标签的启动恢复不会产生逐事件的 O(n) 重复对齐，也不会产生磁盘写入。

## 消息协议（新增）
- `getTreeStructure`
  - 参数：`{ windowIds?: number[] }`（缺省返回所有窗口）
  - 返回：`{ ok, structures: { [windowId]: { parents: { [tabId]: parentTabId } } } }`
    —— `parents` **只包含有父标签的条目**，缺省即顶层（10K 标签下可省掉约一半载荷）。
  - 用途：管理页渲染树状视图。只传父子映射，深度、折叠、渲染顺序都在 UI 侧计算，避免额外的 IPC 体积。
- `moveTabTree`
  - 参数：`{ tabId, parentId, afterTabId?, beforeTabId? }`（`parentId` 为 `null` 表示顶层）
  - 返回：`{ ok, moved, skipped, parentId }` 或 `{ ok: false, error }`（中文提示）
  - 语义：先改父子关系，再用一次（可分批）`chrome.tabs.move` 把「被拖标签 + 其整棵子树」按 DFS 顺序落到目标位置。
  - 校验：拒绝跨窗口、拒绝固定标签参与父子、拒绝挂到自身或自身子孙之下。
- 折叠状态由管理页直接读写 `chrome.storage.session`，不经后台。

## 管理页交互
### 视图切换
- 「打开的窗口」视图标题栏新增「树状 / 平铺」切换按钮。
- 默认 **树状**；选择写入 `chrome.storage.local` 的 `treeViewMode`（全局一份，切换时写一次，写入量可忽略）。

### 树状渲染
- 渲染顺序为**树的 DFS 顺序**：父 → 其整棵子树 → 下一个兄弟；兄弟之间按 `index` 升序。
- 行高保持 44px 不变（复用现有 `VirtualList`）；层级用左侧缩进（每层 16px，超过 12 层不再增加）与层级连线表示。
- 有子标签的行显示折叠三角（▸ / ▾）；点击即折叠 / 展开，只影响视图。
- 折叠状态存 `chrome.storage.session` 的 `treeCollapsed`；切换时立即更新视图，写入防抖 500ms。
- 深度由 UI 侧一次 O(n) 计算，不额外占用 IPC。

### 与筛选、选择的关系
- **过滤模式**：保留「匹配项 + 其全部祖先」；祖先行以非匹配样式展示，且不计入「匹配数」；某窗口整组无匹配则隐藏该窗口。
- **跳转模式**：保持完整树，匹配行高亮，↑ / ↓ 在当前树的可见行之间循环跳转。
- **折叠与筛选**：只要存在关键词（两种模式都算），渲染时就**忽略折叠状态**（自动全展开），
  保证匹配项一定可见、↑/↓ 能跳到每一个匹配项；清除关键词后恢复用户的折叠状态。
- **被隐藏标签的子标签就近提升**：开启「隐藏已冻结」后，若某标签的父标签不可见，则把它提升到最近的可见祖先之下，
  避免出现「父行不显示、子行却缩进」的悬空行。
- **全选 / 清空**：过滤模式只作用于真正匹配的标签（祖先只是路径，不参与批量操作）；跳转模式作用于完整列表。
- 选中集合仍按 `tabId` 记录，与平铺模式完全一致。

### 拖拽
- 树状模式下拖拽**仅限同一窗口**；跨窗口请使用现有「移动到」功能。
- 被拖拽标签的**整棵子树**一起移动。
- 落点分区（与 TST 一致）：
  - 行的上 1/4 → 插到该行**之前**，成为其**兄弟**（父 = 目标行的父）；
  - 行的下 1/4 → 插到该行**之后**（含该行整棵子树之后），成为其**兄弟**；
  - 行的中间 1/2 → 成为该行的**子标签**，追加为其**最后一个子标签**。
- 拖拽过程中显示落点指示（兄弟 → 插入线；子标签 → 目标行高亮）。
- **无效落点**（目标是自身或自身后代、目标或被拖项是固定标签、跨窗口）→ 不显示指示、不触发操作。
- 拖拽结束后：先更新后台内存树，再用一次（可分批）`chrome.tabs.move` 把「被拖标签 + 其子树」按 DFS 顺序移动到目标物理位置，使物理顺序向树顺序靠拢。
- 这是**除跨窗口子树迁移外，插件唯一会移动标签页的场景**；非用户操作时插件绝不移动标签页。

### 位置稳定性
- 树视图按 DFS 顺序渲染，可能与浏览器标签栏的物理顺序不一致（例如某子标签物理上离父标签很远，仍会显示在父标签正下方）。这是**有意设计**：插件不为了「子树物理连续」而在用户未操作时改动标签栏。
- 原生标签栏拖动会按位置重新推断父子（规则 3），因此用户在标签栏里的拖动依然能改变树。

## 性能验收
- `scripts/bench_tree.mjs`（`npm run bench:tree`）对 `background/tree_core.js` 的纯函数做 10K 级基准：
  - 从 10K 标签构建树（含不变量校验）；
  - 从 10K 标签生成快照并序列化（输出字节数）；
  - 会话恢复对齐：完全一致 / 头部插入 200 / 中间插入 100 / 关闭 50 / 局部乱序 100 组 / 5% 完全乱序；
  - DFS 扁平化（折叠与全展开）、单次关闭提升、单次位置推断。
- 阈值（超出即失败）：建树 < 50ms、快照编码 < 50ms、对齐 < 100ms、扁平化 < 30ms；实际耗时约为阈值的 1/5~1/3。
- 单窗口 10K 标签的快照体积：约 1.2MB（含标题）/ 0.5MB（不含标题），低于默认 10MB 的 `storage.local` 配额。
- 复杂度要求：以上全部为 O(n) 或 O(n log n)，禁止 O(n²)。基准脚本会同时校验不变量（父在子前、固定标签不参与父子），
  防止为了性能牺牲正确性。
- `scripts/test_tree.mjs`（`npm run test:tree`）用一套 chrome API 模拟覆盖后台事件链路：
  建树、创建挂载、关闭提升（唯一子标签 / 多子标签）、原生拖动重推断、管理页拖拽、非法拖拽拒绝、
  跨窗口子树迁移、落盘与重启恢复。

## 已知限制
- Chrome 无 Firefox `sessions.setTabValue` 级别的稳定标签标识，因此跨浏览器重启的树恢复是**尽力而为**：URL 变化、顺序大幅变化、或大量重复 URL 时可能退化为顶层。
- Chrome 下 `openerTabId` 在部分场景并不可靠（例如 Ctrl+T），需要靠位置规则与快照对齐纠正。
- 不参与 `chrome.tabGroups` 原生分组。
- 折叠状态不跨浏览器重启保留。
