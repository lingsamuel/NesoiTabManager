# 树恢复等待与后台实例同步

## 已确认的问题与范围

2026-10-04 的 0.2.39 日志记录：新后台已经恢复新标签的正确父关系，但侧边栏在接收实例切换通知后，仍以旧实例版本 8 拒绝新实例版本 1、2、3。当前实现也可复现。另有事件在内存树不存在时直接返回，导致正常落位规则未执行。

用户已确认约 2000 标签时 0.3～0.4 秒的恢复等待可以接受，并授权执行修复：缺少树时，依赖树的操作等待恢复。

本次复用现有按窗口加载、快照恢复、关闭继承、移动与诊断代码，不引入第二份持久化树。Reload 后 URL 身份匹配存在独立风险，但原始恢复日志已丢失；此次不改写匹配算法，也不宣称解决所有历史升顶层问题。

## 行为约束

- 同一窗口的恢复只执行一次；恢复尚未完成时，不把临时缓存视为可读的最终结果。
- 创建、关闭、移动等结构事件不能因缓存缺失而被丢弃；等待恢复后继续各自既有规则。
- 新建时的落位标记和活动标签依据在事件到达时保留；恢复查询已包含新标签时不得再次整体增加下标。
- 查询完成后才到达的创建/关闭事件也必须衔接；已经关闭的标签不能被迟到的创建回调重新插入。
- 关闭仍复用既有提升规则。热缓存路径保持关闭现场采集与提升之间的同步约定；冷路径完成后刷新受影响的会话引用。
- 窗口关闭时取消在途加载，禁止加载完成后复活已关闭窗口的缓存。
- 加载失败不返回看似成功的空父映射；读请求报告失败，后续请求可重试。
- 实例标识继续采用现有随机令牌，版本号继续在实例内递增；通知中的实例标识与每个窗口实际采用结构的实例标识分开。
- 不同实例的版本号不能比较大小。新实例通知/响应已被确认后，旧实例迟到响应不能覆盖新结构；多窗口响应分别判断。
- 前端未能采用所需结构时不能仍把诊断标为已对齐。
- 侧边栏在结构成功加载前保留原列表，避免新标签先以未知父关系显示为顶层。
- 浏览器真正启动时保留既有静默期；已在缓存中的会话恢复标签不重新套用新建规则，静默期间缓存缺失的新增标签仍要登记。普通后台重启不额外增加静默等待。

## 实现边界

- 按窗口复用同一个加载 Promise，另用事件队列衔接加载空档；读请求与落盘等待该窗口队列完成。
- 已观测的关闭与跨窗口移出保留必要的临时现场，让既有提升和迁移逻辑按事件顺序执行。包括恢复期间刚创建又关闭的父项，其存活子项仍能正常继承。
- 关闭内容在浏览器事件到达时采集；父子关系在树就绪后、提升前采集，避免撤销关闭记录写入未知结构。
- 窗口关闭会取消恢复，包括尚在等待启动静默期的请求。查询和快照读取错误向上传递，落盘查询失败保留脏窗口供调度重试。
- 同步关闭现场接口保留同步约定，由已就绪的调用链使用；撤销恢复的异步辅助接口同样等待树和事件队列。
- 前端分别记录最新观察到的后台实例和各窗口实际采用结构的实例。旧实例令牌仅在当前页面内保留，用于拒绝迟到通知和响应，不持久化树或新增身份存储。

## 实施与验证计划

1. 前端：在真实 `useTree` 上补充旧版本 8 → 新实例版本 1、通知/响应不同到达顺序、多窗口、迟到旧响应的失败回归；再修正实例判断与加载结果。
2. 后台：在真实 `tree.js` 上延迟存储/浏览器查询，验证冷创建、冷关闭、加载空档事件、窗口取消、失败重试和并发读共享恢复；再完善现有加载入口与事件等待。
3. 集成：核查侧边栏显示及会话引用写入的先后关系，验证未完成恢复不作为成功对齐状态发布。
4. 跑完整树测试、诊断测试及 Chrome/Firefox 构建；版本统一更新为 0.2.42。完成审查后签名提交，生成主工作区安装包。

## 验证结果

验证覆盖：

- 真实后台模块的 18 个等待与恢复场景：冷创建、冷关闭、加载空档创建、创建父子后关闭新父项、移动、跨窗往返、冷热批量关闭一致性、窗口取消、查询/存储失败重试、落盘失败重试、撤销辅助入口、启动静默与事件风暴。
- 真实前端实例切换测试：旧实例版本 8 → 新实例版本 1、通知/响应先后、多窗口、迟到旧响应及缺失结构；同时覆盖诊断开关两种状态。
- 真实 Vue 侧边栏：结构延迟时不提前显示新标签，失败保留旧列表，过期刷新不覆盖新状态，结构通知不会导致永久刷新循环。
- 冷关闭撤销记录保留原父、内容和被提升子项；关闭定位另经 100 组冷热随机对照验证。
- Node 模拟浏览器 API 的 2000 标签创建突发检查：71 ms、快照读取 1 次、最终结构完整。该数字仅反映本机模拟环境，不代表 Firefox IPC、存储与绘制耗时。

交付验证：`npm run test:tree`、`npm run test:diagnostics`、`npm run build` 均通过；Chrome/Firefox 0.2.42 压缩包完整性、清单版本与后台入口检查通过。复审发现的连续创建关闭和启动风暴漏事件均已修复并复验。

尚未在用户的 Firefox 长期运行环境中复验；原先日志缺失的 Reload 身份匹配问题继续由现有诊断监测。
