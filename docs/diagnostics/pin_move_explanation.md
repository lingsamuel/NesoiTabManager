# 固定标签移动的诊断解释

## 问题与范围

0.2.42 日志中，标签 #12353 从物理位置 2011 移至 3，同时固定标签数量从 3 增至 4。后台将其记录为来源未知的移动，前端将其记录为顺序异常。当前监测器可以用正常 pin 操作复现同样报告。

用户已批准修复：精确解释 pin/unpin 引起的位置变化，继续检测其他标签之间的异常换位。本次仅改诊断链路，不改变树继承、固定标签的产品行为或浏览器原生顺序。

## 约束与实现

- 固定变化来自真实 onUpdated 的 pinned 字段；后台与 onMoved 的同一标签、窗口、位置和移动方向关联，兼容两种到达顺序。
- 原始移动仍记录。待事件处理完成后再确认未知移动；已经确认的疑点若后来收到匹配固定事件，记录恢复原因。不能用后续固定消除该标签之前多个未解释移动。
- 前后完整物理快照中，只有明确改变固定状态且落在固定/普通边界的标签可以解释自身移动。其余共同存活标签继续通过既有相对顺序比较器检测。
- 前端跨后台实例保留的基线同样能解释固定变化，不依赖后台版本号前进。
- 固定事件关联记录有容量边界；关闭诊断、关闭窗口和复位基线时清理。不新增查询、定时器、权限或持久化树。
- 其他未被解释的窗口结构事件会使旧固定位置失效，防止原地固定后被插入平移的标签在后来拖回旧位置时错误关联。移动处理已有的 get 返回值作为迟到关联依据；普通拖动后再固定不能解释旧拖动。
- 原异常包的恢复仍在该包涉及的身份范围内比较，避免后续独立换位妨碍原问题恢复；固定解释只投影已证实的变化项。
- pin 解释仅影响顺序诊断，不能豁免父关系或结构不变量异常。

## 验证

先补失败回归，再验证 pin/unpin、两种事件顺序、冷后台、多个固定变化、固定期间其他标签换位、固定后未知移动、跨实例前端与诊断关闭清理。交付前运行完整诊断测试、树测试及双浏览器构建，版本更新为 0.2.43。

实际验证：12 个后台事件关联场景、5 个新增监测器场景及真实前端 2012 标签跨实例 pin 场景通过。其他标签换位、旧固定标记误关联、迟到固定误解释旧拖动与独立换位恢复均有回归覆盖。`npm run test:diagnostics`、`npm run test:tree`、`npm run build` 均通过。

已有异常日志保留，更新不会将旧版本缺少固定事件证据的历史报告自动改为正常；新版本复验应使用清空后的日志。
