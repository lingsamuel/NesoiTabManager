# 后台重建时的关闭继承修复

## 目标与证据边界

2026-10-04 的复现中，05:47:04 关闭顶层标签 #12156 时后台没有已加载的树；快照重建将其四个子标签全部设为顶层。正常关闭则应让第一个子标签接替原位置，其余子标签归到它下面。此问题已由当前代码的最小复现确认。

本次统一这两条路径的继承规则，并补齐持续打开的侧边栏跨后台实例的观测。此前“关闭非根节点导致孩子升到顶层”的问题尚未定位，继续监测，不宣称随本次修复解决。

## 继承规则

- 关闭顶层节点：第一个存活子节点接替顶层位置，其余子节点归到它下面。
- 关闭父节点的唯一孩子：其所有子节点接回父节点。
- 关闭有兄弟的节点：第一个子节点接回父节点，其余归到第一个子节点下面。
- 所有后代内部关系保留；第一个按当前浏览器物理顺序选择，不按 Map 插入顺序。

复用同一个规则选择函数，正常关闭继续使用现有树修改 API。快照先完成身份匹配，再依据同一规则消去未匹配节点。快照中的合法父下标必须小于子下标；批量消去采用逆快照顺序，先处理后代。快照不含事件时间线，多个缺失节点的真实关闭先后无法恢复，以上是明确的确定性降级顺序。

使用可拼接的存活根列表承接连续缺失祖先，避免长链反复重写全部子孙。每个存活节点只有在确定最终父节点时才写入关系，保持线性结构恢复。最终仍通过现有物理顺序、固定标签等校验。
