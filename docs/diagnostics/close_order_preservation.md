# 关闭父项时保持子树位置

## 已确认的行为与证据

用户允许关闭父项时调整浏览器原生标签顺序。目标：有连续关闭前态时，存活标签在树视图中的相对次序保持关闭前的次序，子树原地接替父项；父关系继续使用现有关闭继承规则。

日志中 #12121 的物理下标为 1879，子项 #12147 为 1891；视图将子项显示在父项下面。关闭后父关系正确，但物理位置未调整，子项的显示下标从 1878 变成 1888，越过 11 个标签。当前纯算法可精确复现，不依赖并发、URL 或内存损坏。

## 实现约束

- 复用 `flattenTree`、`collectSubtreeIds` 和 `applyRemovePromotion`；不建立独立持久化排序体系。
- 同步完成关闭的父关系更新，保留最近关闭记录在同一事件栈结束后读取提升结果的约定。
- 只有视图顺序确实会改变时才定位；移动关闭前 DFS 顺序中的整个存活后代块，放到关闭项原物理位置。不重排整个窗口或无关子树，不改变固定标签。
- 物理定位按窗口串行。队列只在操作期间保留目标物理序列，连续关闭基于上一项的目标位置计算，避免反复使用尚未完成移动的旧下标。
- 移动前按真实窗口列表过滤已关闭项，使用存活锚点确定插入位置。复用内部移动标记，防止原生移动事件再次推断父关系。
- 关闭定位采用严格目标模式：浏览器移动失败不能重试到窗口末尾；若确认有移动成员在途中被关闭，过滤消失成员后向原目标重试。其它失败同步实际下标并取消依赖前置成功的排队计划，记录失败，让监测继续保留不一致。
- 结构响应与落盘等待定位完成。落盘查询前后校验窗口变化，过期查询不能纠偏当前树或写入快照。移动结束更新结构版本，使前端重新查询标签及结构。
- 后台重新加载时，仅在同一会话身份可靠、没有新增身份、共同存活项物理相对顺序与快照一致时，依据快照前态定位缺失父项的后代块。身份或顺序证据不足时不凭 URL 猜测主动移动标签。缺少完整关闭时间线且多个祖先缺失时，块内顺序服从既有恢复算法的最终父关系，仅恢复子树块相对于其它树的外部位置，不承诺重放原快照 DFS。
- 诊断将实际内部定位登记为明确的移动操作，保留精确目标顺序；不把任意关闭换位都视为正常。

## 验证结果

- 8 项专项测试，包括 300 棵随机交错树、冷加载多祖先与多独立块、无需移动的冷加载、并发新增/删除及失败取消。
- 真实后台集成覆盖移动事件先于/晚于 API 回调、期间再关闭和迟到查询；原树集成扩展到 108 项断言。
- 真实 Vue 侧边栏验证迟到的旧标签查询不能覆盖定位后的列表；后台诊断验证正确内部定位不会留下活动异常。
- `npm run test:tree`、`npm run test:diagnostics`、`npm run build` 全部通过；2,000 标签样本仅移动 3 个受影响后代，单次纯规划约 2 ms。
- 测试通过模拟浏览器 API 控制时序，仍需在用户长期运行的 Firefox 窗口中继续验证。此前非根节点错误升顶层问题继续监测。
