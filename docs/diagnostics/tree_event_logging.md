# 树结构诊断日志改进规格

日期：2026-10-03

状态：用户已确认，已实现于 0.2.38；本规格不代表标签关闭异常已经定位。

## 目标与边界

在 Firefox 侧边栏持续打开、窗口约有 2000 个标签的日常使用环境中，不依赖 DevTools，自动发现人眼可能漏掉的顺序或层级变化，记录足以追溯变化的证据，并从设置页导出。

本次完善自动监测、诊断采集、过滤、保存及导出，不改变关闭提升、父关系推断、快照对齐、前端版本判定或浏览器标签移动规则。不新增扩展权限，不主动保持后台存活，不增加定期查询全部浏览器标签的任务。

沿用现有调试开关和复制日志入口。调试关闭时不采集结构快照，不发送诊断消息；诊断失败不得阻断正常标签操作。

## 自动监测

### 启用与观测边界

开启现有“调试模式”总开关后自动运行监测，无需用户先发现异常或手动点击检查。“详细结构”子开关控制普通事件的上下文输出；自动监测发现异常时，即使未开详细子开关，也保留必要的局部证据。

监测复用已有浏览器事件、后台结构操作及其异步完成点、标签查询结果和前端行模型更新。每个窗口、每种数据来源分别维护上一份观测基线；首次观测只建立基线，不把整个窗口视为新增异常。

浏览器物理顺序、后台缓存 index 顺序、完整树行模型及筛选/折叠后的可见行顺序分别记录来源。物理顺序不要求等于树的 DFS 顺序；不能因为两者不同就报告错误。

收到移动事件时立即记录原始 tabId、窗口、fromIndex、toIndex 及已知操作关联，再进入既有业务处理，包括插件内部移动被业务逻辑忽略的事件。不能只依赖 250 ms 防抖后的最终快照，否则“两次交换后恢复原样”可能完全消失。前端也在自身行模型实际应用时观察变化，保留对应请求与状态信息。

该机制覆盖观测点收到的事件和状态，不能承诺发现未产生可观测事件、又在两次状态采样之间恢复的瞬时变化。后台或侧边栏不运行、页面隐藏期间未执行的渲染检查、以及恢复基线不可用的时段，必须标记监测间断，不把间断跨越的变化当成已追踪的完整过程。重新可见时复用现有刷新结果重建或核对基线，不轮询唤醒后台。

### 顺序变化检测

对连续两次观测，先取同窗口、同来源的共同存活标签，将两份序列投影到该集合，精确比较相对顺序。以稳定 tabId 判定身份，不依赖 URL、标题、节点总数或简单求和摘要。

- 删除 D 后，其余标签 index 整体减一，但共同存活标签相对顺序未变：归为正常位移，使用范围摘要。
- 两个标签从 E、F 变成 F、E：即使只相差一个位置、节点数及内容完全相同，也生成明确的顺序变化记录，包含双方原来的及当前的相邻节点。
- 插入新标签、批量关闭和跨窗口迁入迁出：先排除新增/离开项对数值 index 的影响，再比较存活项，避免误报成换位。
- 筛选、折叠或固定标签区域变化：记录状态原因，区分可见集合变化和存活可见项的顺序变化，不要求被隐藏节点仍有可见行。

比较采用线性扫描和 ID 到位置的映射，不做全体标签两两比较，不用可能碰撞的摘要代替最终精确判定。差异检测复用日志的同一份差异结果；只在格式化输出阶段过滤无关节点，不能先过滤再检测，从而漏掉操作范围外的换位。

### 结构检查与异常判定

监测还只读检查原始父引用是否有效、父子索引是否一致、是否有环或重复节点、层级变化是否有对应结构操作，以及前端接受的版本与实际应用结果是否一致。复用项目已有的结构约束和行模型能力；不能通过调用会修正树的清理函数来“检查”，也不维护另一套业务树或复制关闭提升算法作为所谓正确答案。

检测结果分为以下类别：

- **已解释变化**：有已登记操作及相符的作用范围或显示状态变化，例如显式移动、正常关闭提升或折叠；仍保留简短变化证据，不弹异常提示。
- **可疑变化**：存在相对顺序翻转、非预期作用范围内的改父或层级变化，却缺少足够因果信息。记录可疑而非直接断言发生 Bug。浏览器 onMoved 本身只能证明发生了移动，不能证明用户主动拖动或该移动合理。
- **结构不一致**：在可对齐的观测点发现悬空父、索引不一致、环、重复节点，或相同后台实例/结构版本及兼容标签集合下的前后台不一致，明确报告违反的约束。

异步流程尚未结束、标签查询与结构响应期间又发生新事件、后台实例变化等情况下，保留即时观测并标记“处理中/无法对齐”。后续正常观测再确认或解除疑点，不靠固定延时就宣称数据已经稳定，也不能把其他时刻的两个快照直接当成确定不一致。同一原因登记并不能自动解释任意变动，至少要核对事件类型、相关标签、操作阶段和作用范围。

### 自动保留现场与提示

首次发现可疑变化或结构不一致时创建异常记录包，保留相关节点的上一基线、当前状态、局部父链/相邻节点、相关事件及请求关联信息；后续已观测到的相关操作结果补入同一记录包。若无法提供前序或后续证据，明确标注缺失，不虚构完整现场。

同一未恢复问题按窗口、异常类型及涉及节点合并计数，保留首次和最近发现时间；恢复后再出现算作新一轮问题。正常关闭产生的大量相同 index 位移不累积异常计数。

异常记录包使用独立的预留容量，防止日常日志很快冲掉难得的现场。侧边栏和设置页显示非阻断提示“检测到可疑结构变化”及计数，并提供已有诊断导出入口；不弹模态框、不抢焦点、不自动滚动或展开树，也不自动修复、回滚、重排标签。只有完成对齐并通过后续检查才能标记恢复，提示中已捕获记录仍可导出。

## 输出范围与过滤

推荐范围为操作节点的完整子树、必要父链和相邻兄弟；例如关闭 A 下的 D，保留 D、E、F 及其后代、A 的祖先链、D 相邻的兄弟节点，不因 A 有其他未变分支就全部打印。这一范围按操作前后两份结构取并集，避免提升后子树已经脱离而遗漏。

此外，以下节点无论是否位于推荐范围，都进入详细记录：

- 新增、删除或原始父关系变化的节点。
- 层级、内容或非统一位移的位置发生变化的节点。
- 父引用悬空、父子索引不一致、无法确定层级等异常涉及的节点。

范围外且 index、层级、父关系、内容均相同的节点不逐项输出，记录省略数量。内容比较覆盖标题和 URL；比较使用临时快照，不将标题或 URL 正文写入诊断记录，只记录变化标志。

仅发生统一 index 位移的无关节点另行汇总：例如关闭 D 后后方节点整体左移一位，记录变化前后范围、位移量、节点数和边界节点 ID，不输出上千行 `index -1`。仅在节点身份及相对顺序相同、父关系与层级及内容未变、位移量一致时允许合并；不能只根据区间两端猜测中间节点未变。无法确认时保留明细。

同一节点的前后状态放在一条变更记录中；涉及范围内未变的节点只输出一份上下文，不重复打印两遍整棵树。输出包含窗口标签总数、详细节点数、完整省略数、批量位移数量。

## 保留原始证据

记录中的原始父 ID 与界面渲染结果分开表达。父 ID 指向缺失节点时明确记录悬空引用，不能用树形缩进替代父 ID，更不能把渲染时的顶级回退当成父关系原本就是 null。

局部记录至少包含：标签 ID、操作前后原始父 ID、父是否存在、索引、层级和内容变化标志。后台缓存的 index 与浏览器查询取得的 index 明确标注来源，不能混用名称造成误判。

采集同时核对父映射与子节点索引，报告多余、缺失或归属不一致的索引项。涉及范围的计算不能只依赖可能有问题的子节点索引；复用现有父映射、子索引构建及行模型能力，不另写一套树维护算法。

正常路径可做线性的快照比较，但先筛选节点，再生成文本；避免逐节点重复遍历父链及无关整窗文本的排序和拼接。快照只用于诊断，不写回业务树。

## 事件与前后台关联

每条新日志带采集时间、来源实例 ID、来源递增序号、事件类型和窗口 ID。异步操作带关联 ID，起止及后续结果沿用关联 ID。前端消息额外保留前端采集时间和后台接收时间；不把跨上下文消息到达顺序误称为真实执行顺序。

后台记录浏览器结构事件、关闭处理前后、父关系改写原因、落盘纠偏，以及结构请求返回的版本与后台实例令牌。关闭处理的结束记录即使发生异常也尽力生成，并明确异常位置；已有原因日志复用统一出口。

前端使用请求关联 ID 记录结构请求、收到的令牌和版本、本地已知版本、接受或丢弃的决定及原因。侧边栏还记录该轮标签查询与行模型应用结果，包括相关节点的原始父 ID、实际层级和必要的过滤/折叠状态。

以上信息用于区分“关闭处理已错”“随后被其他流程覆盖”“后台正确而前端应用或显示异常”。诊断不顺便修复版本比较或改变请求执行顺序。

前端诊断按批发送并限制载荷；后台对收到的字段和长度做校验。只发送诊断所需字段，不发送标签标题、URL 或用户页面内容。

## 缓存与保存可靠性

复用现有后台日志入口及 `storage.session` 保存方式；将缓冲、恢复和保存职责与树差异格式化分开，避免继续把逻辑堆进树集成模块。

- 普通缓冲同时限制记录数与序列化字节数，默认最多 800 条、1 MiB，以先达到者为准；优先淘汰较旧记录并累计淘汰计数。
- 异常记录包另预留 1 MiB，最多 4 包：保留首个尚未清空的异常包及最近 3 包。单包最多 256 KiB，其中每条详情仍受下述 128 KiB 限制；超限时保留首次与最新证据并明确标记截断。两个区域的日志内容总预算为 2 MiB，元数据另行计量并留存储余量。复制导出不会隐式清空异常包，只有用户执行清空操作才清除首个包。
- 单次事件详情最多 128 KiB。优先保留实际变化和异常，再保留上下文；超限时明确标记记录不完整、原始节点数和省略类别，不能静默截断后称为完整现场。
- 每 400 ms 合并保存一次，保存串行执行；正在保存期间产生的新记录仍保持待保存状态，避免写完旧快照就误认为全部保存完成。
- 恢复旧日志只启动一次，并与恢复期间的新日志合并；清空操作使用代次标记，防止较晚返回的旧读取重新恢复已清空内容。兼容旧字符串数组，但明确旧记录缺少新元数据。
- 保存检查同步异常及 `runtime.lastError`。失败保留当前内存记录与待保存状态，更新可见错误信息；下一批或显式导出时可重试，不进行无上限的紧密重试。
- 配额失败时允许减少较旧缓存后进行一次受控重试，记录被淘汰数量；仍失败则如实报告，不宣称已持久保存。

会话存储不等于磁盘持久存储。本次不承诺浏览器退出、扩展重载或进程崩溃后日志仍可恢复；正在正常运行时，导出不依赖缓存已经成功保存，也不要求打开控制台。

## 导出与设置页

“复制调试日志”等待旧日志恢复完成，再导出当前缓冲，包含尚未保存的新记录。恢复失败时仍可导出当前记录，并在导出头部说明历史记录不可用。

导出头部包含扩展版本、日志格式版本、记录时间范围、缓存字节数、淘汰/截断计数、最新保存状态及错误，并列出监测间断和异常记录包摘要。不把读取失败显示成“还没有日志”。

设置页说明改为“无需打开 DevTools，自动监测发现可疑变化后可直接复制日志”，并显示监测状态、异常计数、保存异常或内容不完整状态。保持已有两个开关；详细开关改为描述局部结构与变化证据，不再宣称打印整个窗口。

## 验证与交付

先为已确认的日志缺陷及以下行为增加失败测试，再实施对应修复：

1. 2000 标签窗口中关闭小子树：无关完全未变分支被省略，统一 index 位移压缩，相关子树与父链仍在。
2. 无关分支真的改父、改层级或改内容时不能被误过滤；非统一位移不能被批量摘要掩盖。
3. 真正顶级、父缺失和子索引不一致在输出中可区分；过滤后仍保留原始层级，不按剪枝后的局部树重新推断。
4. 旧日志恢复期间新事件不会丢失，重复初始化不会重复合并，清空与恢复/保存交错不会恢复旧内容。
5. 写入报错、配额失败和异步保存交错可观察，未保存内容仍能导出；字节限额、长单条记录和淘汰计数符合规则。
6. 后台结构响应与前端接受/丢弃记录能够对应；诊断关闭不额外发消息，诊断失败不改变正常操作。
7. 模拟不开 DevTools 的连续记录、保存、恢复和导出流程；不把模拟测试表述为真实 Firefox 复现。
8. 2000 标签中两个标签互换位置，即使标题、URL、父项和层级均不变，也能检测；分别覆盖浏览器物理序列换位和物理序列未变但侧边栏行序列换位。
9. 普通插入/删除造成的整体 index 位移不误报；明确操作对应的移动、筛选、折叠与跨窗口迁移被正确分类；来源未知的 onMoved 不被自动当作用户意图。
10. 防抖期间先换位再换回，原始移动事件仍在；无法对齐的异步中间态不会被直接断言为确定错误，后续确认与恢复均有证据。
11. 异常发生在本次操作子树之外仍能捕获；持续同一异常合并计数，正常日志淘汰不覆盖预留的首次异常现场；关闭调试后监测停止。
12. 监测过程中不会调用移动、改父、清理修复或主动保活逻辑；基线缺失、页面隐藏、实例变化和超限均明确标记覆盖边界。

运行相关日志与树结构回归测试，并验证 Firefox/Chrome 构建。使用 2000 标签样本记录输出体积和耗时；只在实际完成浏览器验证后才声称通过真实浏览器测试。

实现完成时统一将 `package.json` 与 `manifest.json` 的 patch 版本更新一次，创建中文提交；不包含用户已有的 AGENTS.md 改动。


## 使用与实现边界（0.2.38）

在设置页开启“调试模式”即可自动监测；详细开关补充普通操作的局部结构证据。两种模式均不导出标题、网址或页面正文。可疑变化经对齐确认后在侧边栏与设置页提示，直接使用“复制日志”；不需要打开 DevTools。未知来源的浏览器移动表示已观测到移动，不能单凭它确认用户意图或断言 Bug。

异步查询的新标签集合可能先于父映射到达：此时只保留处理中观测，若在下一次可对齐观察恢复，不累计异常包；若仍异常，首次异常包带上之前的证据。显式移动的预期物理顺序由既有业务结果提供，前端通过现有行模型转成各自来源的预期顺序。后台最多随响应携带最近 32 次已完成操作供前端核对。

为限制长时间运行内存，单来源最多跟踪 32 个未恢复问题、后台最多跟踪 128 个未知移动；超限或显示投影切换均明确记录观测边界。异常包的前后相关事件最多保留 8 条（首次 4 条及最近 4 条，每条最多 2 KiB）；身份串超出 48 KiB 时标记无法可靠合并，不将截断身份误合并。前端单条 24 KiB、单批 96 KiB/64 条、队列 256 KiB；这些传输截断在导出中保留，并显示记录不完整。

验证入口：`npm run test:diagnostics`、`npm run test:tree`、`npm run build`。2000 标签正常关闭的纯比较样本输出 2407 bytes，开发环境单次约 10 ms；该数字只代表模拟样本。测试覆盖恢复/清空/写入交错、存储失败、双换位、处理中确认/恢复、跨来源隔离、前后版本关联与隐私边界。Firefox 与 Chrome 构建可验证；未在真实 Firefox 的 2000 标签长期运行环境复现原问题。

旧格式字符串日志无法可靠区分标题和诊断文本，因此仅恢复明确识别出的数值结构字段；导出标明原始记录数、字节数及历史内容受限。客户端最后一批发送失败时，显式复制前仍尝试一次补报观测缺口，不依赖后续标签操作触发。
