# 树结构诊断日志改进规格

日期：2026-10-03

状态：待用户确认；本规格不代表标签关闭异常已经定位。

## 目标与边界

在 Firefox 侧边栏持续打开、窗口约有 2000 个标签的日常使用环境中，不依赖 DevTools，记录足以追溯父关系变化的证据，并从设置页导出。

本次完善诊断采集、过滤、保存及导出，不改变关闭提升、父关系推断、快照对齐、前端版本判定或浏览器标签移动规则。不新增扩展权限，不主动保持后台存活，不增加定期查询全部浏览器标签的任务。

沿用现有调试开关和复制日志入口。调试关闭时不采集结构快照，不发送诊断消息；诊断失败不得阻断正常标签操作。

## 输出范围与过滤

推荐范围为操作节点的完整子树、必要父链和相邻兄弟；例如关闭 A 下的 D，保留 D、E、F 及其后代、A 的祖先链、D 相邻的兄弟节点，不因 A 有其他未变分支就全部打印。这一范围按操作前后两份结构取并集，避免提升后子树已经脱离而遗漏。

此外，以下节点无论是否位于推荐范围，都进入详细记录：

- 新增、删除或原始父关系变化的节点。
- 层级、内容或非统一位移的位置发生变化的节点。
- 父引用悬空、父子索引不一致、无法确定层级等异常涉及的节点。

范围外且 index、层级、父关系、内容均相同的节点不逐项输出，记录省略数量。内容比较覆盖标题和 URL；比较使用临时快照，不将标题或 URL 正文写入诊断记录，只记录变化标志。

仅发生统一 index 位移的无关节点另行汇总：例如关闭 D 后后方节点整体左移一位，记录变化前后范围、位移量、节点数和边界节点 ID，不输出上千行 `index -1`。仅在节点身份及相对顺序相同、父关系与层级及内容未变、位移量一致时允许合并；不能只根据区间两端猜测中间节点未变。无法确认时保留明细。

同一节点的前后状态放在一条变更记录中；涉及范围内未变的节点只输出一份上下文，不重复打印两遍整棵树。输出包含窗口标签总数、详细节点数、完整省略数、批量位移数量。

## 保留原始证据

记录中的原始父 ID 与界面渲染结果分开表达。父 ID 指向缺失节点时明确记录悬空引用，不能用树形缩进替代父 ID，更不能把渲染时的顶级回退当成父关系原本就是 null。

局部记录至少包含：标签 ID、操作前后原始父 ID、父是否存在、索引、层级和内容变化标志。后台缓存的 index 与浏览器查询取得的 index 明确标注来源，不能混用名称造成误判。

采集同时核对父映射与子节点索引，报告多余、缺失或归属不一致的索引项。涉及范围的计算不能只依赖可能有问题的子节点索引；复用现有父映射、子索引构建及行模型能力，不另写一套树维护算法。

正常路径可做线性的快照比较，但先筛选节点，再生成文本；避免逐节点重复遍历父链及无关整窗文本的排序和拼接。快照只用于诊断，不写回业务树。

## 事件与前后台关联

每条新日志带采集时间、来源实例 ID、来源递增序号、事件类型和窗口 ID。异步操作带关联 ID，起止及后续结果沿用关联 ID。前端消息额外保留前端采集时间和后台接收时间；不把跨上下文消息到达顺序误称为真实执行顺序。

后台记录浏览器结构事件、关闭处理前后、父关系改写原因、落盘纠偏，以及结构请求返回的版本与后台实例令牌。关闭处理的结束记录即使发生异常也尽力生成，并明确异常位置；已有原因日志复用统一出口。

前端使用请求关联 ID 记录结构请求、收到的令牌和版本、本地已知版本、接受或丢弃的决定及原因。侧边栏还记录该轮标签查询与行模型应用结果，包括相关节点的原始父 ID、实际层级和必要的过滤/折叠状态。

以上信息用于区分“关闭处理已错”“随后被其他流程覆盖”“后台正确而前端应用或显示异常”。诊断不顺便修复版本比较或改变请求执行顺序。

前端诊断按批发送并限制载荷；后台对收到的字段和长度做校验。只发送诊断所需字段，不发送标签标题、URL 或用户页面内容。

## 缓存与保存可靠性

复用现有后台日志入口及 `storage.session` 保存方式；将缓冲、恢复和保存职责与树差异格式化分开，避免继续把逻辑堆进树集成模块。

- 新缓冲同时限制记录数与序列化字节数，默认最多 800 条、2 MiB，以先达到者为准；优先淘汰较旧记录并累计淘汰计数。
- 单次事件详情最多 128 KiB。优先保留实际变化和异常，再保留上下文；超限时明确标记记录不完整、原始节点数和省略类别，不能静默截断后称为完整现场。
- 每 400 ms 合并保存一次，保存串行执行；正在保存期间产生的新记录仍保持待保存状态，避免写完旧快照就误认为全部保存完成。
- 恢复旧日志只启动一次，并与恢复期间的新日志合并；清空操作使用代次标记，防止较晚返回的旧读取重新恢复已清空内容。兼容旧字符串数组，但明确旧记录缺少新元数据。
- 保存检查同步异常及 `runtime.lastError`。失败保留当前内存记录与待保存状态，更新可见错误信息；下一批或显式导出时可重试，不进行无上限的紧密重试。
- 配额失败时允许减少较旧缓存后进行一次受控重试，记录被淘汰数量；仍失败则如实报告，不宣称已持久保存。

会话存储不等于磁盘持久存储。本次不承诺浏览器退出、扩展重载或进程崩溃后日志仍可恢复；正在正常运行时，导出不依赖缓存已经成功保存，也不要求打开控制台。

## 导出与设置页

“复制调试日志”等待旧日志恢复完成，再导出当前缓冲，包含尚未保存的新记录。恢复失败时仍可导出当前记录，并在导出头部说明历史记录不可用。

导出头部包含扩展版本、日志格式版本、记录时间范围、缓存字节数、淘汰/截断计数、最新保存状态及错误。不把读取失败显示成“还没有日志”。

设置页说明改为“无需打开 DevTools，复现后直接复制日志”，并显示保存异常或内容不完整状态。保持已有两个开关；详细开关改为描述局部结构与变化证据，不再宣称打印整个窗口。

## 验证与交付

先为已确认的日志缺陷及以下行为增加失败测试，再实施对应修复：

1. 2000 标签窗口中关闭小子树：无关完全未变分支被省略，统一 index 位移压缩，相关子树与父链仍在。
2. 无关分支真的改父、改层级或改内容时不能被误过滤；非统一位移不能被批量摘要掩盖。
3. 真正顶级、父缺失和子索引不一致在输出中可区分；过滤后仍保留原始层级，不按剪枝后的局部树重新推断。
4. 旧日志恢复期间新事件不会丢失，重复初始化不会重复合并，清空与恢复/保存交错不会恢复旧内容。
5. 写入报错、配额失败和异步保存交错可观察，未保存内容仍能导出；字节限额、长单条记录和淘汰计数符合规则。
6. 后台结构响应与前端接受/丢弃记录能够对应；诊断关闭不额外发消息，诊断失败不改变正常操作。
7. 模拟不开 DevTools 的连续记录、保存、恢复和导出流程；不把模拟测试表述为真实 Firefox 复现。

运行相关日志与树结构回归测试，并验证 Firefox/Chrome 构建。使用 2000 标签样本记录输出体积和耗时；只在实际完成浏览器验证后才声称通过真实浏览器测试。

实现完成时统一将 `package.json` 与 `manifest.json` 的 patch 版本更新一次，创建中文提交；不包含用户已有的 AGENTS.md 改动。
