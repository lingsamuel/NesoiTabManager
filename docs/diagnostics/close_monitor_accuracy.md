# 关闭继承的诊断误报与重复记录修复

## 范围

0.2.39 的复现中，06:25:44 关闭 #12173 后，#12174 接到 #12164、#12160 接到 #12174，符合正常关闭规则。后台实例切换使操作登记丢失，前端仍将变化持续判为可疑；visibleRows 对重叠节点重复建包，未变化采样重复更新，挤掉较早事件。

本次只修诊断旁路，不改变业务继承规则。原先“非根节点关闭后子节点升到顶层”的原因仍未知，必须继续捕获。

## 判定依据

前端诊断客户端监听实际的 `tabs.onRemoved`，在同一文档生命周期内保留事件顺序。仅在有关闭前已对齐基线、完整父映射和物理顺序，且确认对应节点已离开完整集合时，才在独立副本上调用现有 `applyRemovePromotion`，生成精确预期父关系。对目标父不符的节点、无关闭依据的改父、共同存活节点换位继续报警。隐藏或筛选掉的行不等于关闭。登记有容量边界，关闭诊断、显式 gap、销毁文档都释放记录。无需 DevTools，不增加浏览器查询或保活定时器。

补充推导仅用于没有有效操作登记的采样；已有后台登记保留原顺序。采样间若存在新增身份，旧基线可能不再满足关闭分支条件，保守保留疑点。层级解释复用 `flattenTree` 按当前来源可见身份计算投影，只豁免精确匹配的层级变化。缩进停留在旧值也要检查；已确认的层级问题保留关闭恢复目标，后续新增标签或无关操作不能使错误旧值被判为恢复。

## 异常生命周期与降噪

- 同窗口同来源同类型，在同一已对齐前态下出现的重叠疑点合并，保留最早证据与稳定签名。已经跟踪的节点不另建重复包；新的独立问题仍保留自己的基线。
- rows 与 visibleRows 仍分别观测，避免把视图特有问题与完整树混为一谈。
- 未变化重复采样不重复输出异常包或异常事件；请求 ID、revision 和 pending/complete 往返不单独视为新异常证据。
- 初次确认、异常节点的父/层级/下标/内容/相对顺序或结构问题变化、来源切换、真实恢复必须留证据。去重只减少输出，不停止检测、不把未恢复问题清除。
- 活动问题新增节点时补充该节点的原始前态；最早现场不得被后续暂态覆盖。

## 验证结果

18 项关闭诊断生命周期回归、完整 `test:diagnostics`、`test:tree` 和双浏览器构建通过。实际侧边栏 watcher 集成覆盖关闭响应间隙及后台换实例。2,000 标签重复采样 50 次不增加相同异常记录，局部输出约 10 KB；内容变化继续留证据且不输出正文。
